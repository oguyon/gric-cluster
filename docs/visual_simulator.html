GRIC Simulator Guide & Documentation

Greedy Randomized Incremental Clustering • WebAssembly • Exact Multi-Point Pruning

🚀 Quick Start & Workflow

Welcome to the GRIC Interactive Algorithm Simulator! This web tool visualizes GRIC (Greedy Randomized Incremental Clustering) in real-time, executing the exact high-performance C clustering algorithms compiled into WebAssembly (WASM) with exact parity to the command-line gric-cluster executable.

🌊 What is Streaming Clustering?

Unlike batch clustering methods (e.g. standard k-means or hierarchical agglomeration) that require all points in advance, GRIC operates on infinite temporal data streams. Points are ingested frame by frame, dynamically expanding the cluster dictionary while maintaining tight geometric guarantees on maximum cluster radius rlim.

4-Step Exploration Workflow

  1. Select a Benchmark: Choose from 2D and 3D datasets (e.g. 2Dspiral, 3Dtorus, Lorenz Attractor) or upload your own ASCII/CSV file.
  2. Adjust Radius (rlim): In the Algorithm tab, set the maximum distance threshold for a point to belong to an existing cluster anchor.
  3. Select Heuristics & Pruning: Choose candidate target selection (Greedy vs Shannon Entropy) and geometric pruning (3P, 4P, 5P).
  4. Run & Observe: Click ▶ Play or step through frames with ⏭ Step (S). Check the ⚡ Resource Tracker to see distance evaluations saved.

🔍 3D Multi-View Quad Projections

When running in 3D datasets, the canvas automatically splits into a 4-quadrant layout: Top-Left: X-projection (Y-Z plane) • Top-Right: Y-projection (X-Z plane) • Bottom-Left: Z-projection (X-Y plane) • Bottom-Right: Interactive 3D Orbit Camera (click and drag to rotate).

🎯 Core Algorithm & Radius (rlim)

GRIC is an exact sequential metric clustering algorithm designed for streaming multi-dimensional vectors x ∈ ℝd.

The Radius Threshold (rlim)

The fundamental parameter of GRIC is rlim (ε). Every cluster is represented by a rigid anchor centroid c_j. A point x is eligible for assignment to cluster j if and only if:

d(x, c_j) ≤ rlim

If d(x, c_j) > rlim for all active clusters, point x is instantiated as a brand-new cluster anchor c_{k+1} = x.

📐 Automatic Radius Selection (-scandist / a<factor>)

If the spatial scale of your dataset is unknown, clicking Auto-rlim runs a rapid initial nearest-neighbor scan to measure inter-sample distance percentiles, setting rlim = factor × μNN. In CLI mode, passing a1.5 sets auto-rlim with factor 1.5.

Cluster Capacity & Eviction (-maxcl)

When a maximum cluster limit -maxcl <N> is enforced:

  • Stop (-maxcl_strategy stop): Halts clustering once capacity is reached; excess points are rejected.
  • Discard (-maxcl_strategy discard): Automatically purges the least-frequently visited fraction (-discard_frac 0.1) of clusters.
  • Merge (-maxcl_strategy merge): Merges the closest pair of existing cluster centroids to free up anchor capacity.

📐 Geometric Multi-Point Pruning (3P / 4P / 5P)

Calculating Euclidean distance d(x, c_j) across high dimensions is computationally expensive. GRIC leverages the triangle inequality on the metric space to prove that a candidate cluster cannot match without computing its distance.

| d(x, c_i) - D_cc(i, j) | ≤ d(x, c_j) ≤ d(x, c_i) + D_cc(i, j)

Pruning Modes Explained

1. 3-Point Pruning (3P — Default)

When distance d(x, c_i) to anchor c_i is measured, the lower bound to any unmeasured anchor c_j is:

LB3P(c_j) = | d(x, c_i) - D_cc(i, j) |

If LB3P(c_j) > rlim, cluster c_j is mathematically guaranteed to be outside the matching radius and is immediately pruned.

2. 4-Point Pruning (4P — -te4)

Uses information from two previously measured anchors c_i, c_k simultaneously. By combining pairwise inter-anchor separations D_cc(i, j) and D_cc(k, j), 4P establishes a strictly tighter geometric lower bound:

LB4P(c_j) = max( |d(x, c_i) - D_cc(i, j)|, |d(x, c_k) - D_cc(k, j)| )

3. 5-Point Pruning (5P — -te5)

Precomputes 64-bit consistency bitmasks across cluster triples. When evaluating complex manifolds, 5P prunes entire geometric neighborhoods in a single CPU bitwise AND instruction.

📊 Shannon Entropy Scheduling

Instead of querying cluster anchors in arbitrary or greedy order, GRIC can select measurement targets that maximize Information Gain (ΔH) over the probability distribution of candidate clusters.

H(P) = - ∑j P(c_j) × log2 P(c_j)   [bits]

Target Selection Mechanism (-entropy)

At each step, GRIC simulates the two possible outcomes of measuring cluster c_k:

  1. Match (d ≤ rlim): Assignment found; posterior entropy collapses to 0 bits.
  2. Mismatch (d > rlim): Geometric 3P/4P pruning eliminates a subset of candidate clusters, reducing entropy to Hmismatch.

The target with the largest expected entropy drop ΔH(c_k) = H(P) - 𝔼[H(P | outcome)] is measured first.

⚡ Adaptive Gating Thresholds (-entropy_gate)

Full Shannon entropy calculation has an overhead. When the remaining uncertainty drops below the entropy gate threshold (e.g. H < 0.75 bits), the algorithm automatically switches to instant greedy verification, preserving compute cycles.

🔄 Markov Transitions & Prediction

Streaming data often exhibits strong temporal autocorrelation (e.g. physical trajectories, dynamical systems, periodic orbits). GRIC accelerates clustering by incorporating temporal priors.

1. Markov Transition Matrix (-tm <coeff>)

Tracks the transition frequency T_{i → j} from the previously assigned cluster c_i to cluster c_j. The prior probability for the incoming frame blends geometric and Markov probabilities:

Pprior(c_j) = (1 - α) × Pgeom(c_j) + α × T(cprev, c_j)

2. Sequence Pattern Prediction (-pred)

Maintains a rolling history of recent cluster transitions. It matches the current sequence pattern to predict the most likely destination cluster, probing it as the very first candidate.

3. Geometric Visitor History (-gprob / -maxvis)

Clusters track visitor timestamps and geometric density, biasing search order towards recently active spatial regions.

💬 Explain Mode & Diagnostics

Explain mode transforms the clustering engine into an open, inspectable learning tool.

How to Use Explain Mode

  1. Click 💬 Explain (E) in the toolbar.
  2. Use ⏭ Step (S) to process frames one by one.
  3. Read the Decision Narrative on the right panel to see the exact reasoning behind every anchor tested, distance measured, and candidate pruned.
  4. Inspect the Candidate Rankings Table to see lower/upper distance bounds, prior probabilities, and information gain scores.
  5. Navigate past frame explanations using the [ and ] bracket keys or the history dropdown.

⚡ WASM + Trace Parity

Explain mode is backed directly by a circular trace buffer in the C/WASM engine. The exact internal C variables (TraceEvent) are read from the WebAssembly heap, ensuring 100% fidelity with native execution.

🔲 Subspace Tiling & Multi-Tile (2D/3D)

When clustering vast coordinate spaces or high-rate image sensor streams, GRIC partitions the input domain into an N × M grid of independent sub-tiles (-tiles).

Live Cross-Tile Prior Injection (-xtile)

Maintains a live Co-occurrence Probability Table (CPT) across tile boundaries with exponential decay (-xtile_decay 0.70). When a point enters a tile, active clusters in adjacent tiles provide prior probability boosts.

Joint Trajectory Fusion (Pass 2 / -jtf)

A post-clustering trajectory pass that stitches tile-boundary crossings and eliminates boundary fragmentation artifacts.

🔍 Metric-Pruned k-Nearest Neighbors (gric-knn)

The gric-knn solver calculates all-to-all or causal \(k\)-Nearest Neighbors for every frame using the cluster model pre-built by gric-cluster. It executes the exact same C engine via WebAssembly to achieve 95%–99%+ metric pruning.

🎯 4-Stage Metric Pruning Pipeline

  • Level 1 (Inter-Cluster DCC Bound): \(\text{LB}_q = \max(0, D(a_p, a_q) - r_{\text{home}} - R_q)\). If \(\text{LB}_q \ge \text{heap\_max} / (1+\epsilon)\), skips the entire cluster without inspecting any member frames.
  • Level 2 (Query-to-Anchor Bound): Computes exact distance \(d(x_i, a_q)\). If \(d(x_i, a_q) - R_q \ge \text{heap\_max} / (1+\epsilon)\), prunes cluster \(c_q\).
  • Level 3 (1D Annular Member Filter): Checks \(|d(x_i, a_q) - r_{\text{anc}}(x_j)| \ge \text{heap\_max} / (1+\epsilon)\) before accessing member coordinates.
  • Level 4 (Vectorized Euclidean Distance): Evaluates exact coordinate distance and pushes into bounded top-\(k\) max-heap.

⏱️ Temporal Causal Filtering

  • -dtmin <N>: Excludes self-matches and nearby frames within \(\pm N\) time steps to avoid auto-correlated trivial neighbors.
  • -past: Enforces causal reconstruction by only searching preceding frames (\(j < i\)).
  • -future: Searches only subsequent frames (\(j > i\)).
  • -eps <slack>: \((1+\epsilon)\)-Approximate nearest neighbor search for even higher speedups.

🎨 Distance Line Color Coding

  • 🟢 Solid Green: Sample-to-Cluster solving match (\(d \le r_{\text{lim}}\), cluster allocation winner).
  • 🔴 Dashed Red: Sample-to-Cluster solving mismatch (\(d > r_{\text{lim}}\), candidate rejected).

  • 🟠 Dashed Amber: Other distance computations (incoming queries from other frames to this point).
